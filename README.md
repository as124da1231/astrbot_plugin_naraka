# 永劫无间战绩查询

**当前版本：1.3.5**（更新内容见 [CHANGELOG.md](CHANGELOG.md)）

适用于 AstrBot 4.10.4 及以上版本与 QQ（aiocqhttp）的永劫无间**端游**战绩插件。
按昵称查询小黑盒中的近期对局、单局详情和赛季总览。
数据来自小黑盒的非公开接口，使用前需由管理员扫码登录小黑盒（无绑定模式除外）。

项目地址：[as124da1231/astrbot_plugin_naraka](https://github.com/as124da1231/astrbot_plugin_naraka)。

## 数据模式

插件有三种数据模式，在配置页的「数据模式」里三选一：

| 模式 | 登录方式 | 可用能力 |
| --- | --- | --- |
| `heybox`（默认） | `/永劫登录` 发**小黑盒 App 二维码** | 全量查询（战绩/详情/赛季）+ 自动绑定兜底 |
| `wechat` | `/永劫登录` 发**微信扫码二维码** | 与 `heybox` **完全等价**，只是扫码渠道不同 |
| `none` | **不需要登录**，`/永劫登录` 会提示无需登录 | 只走免登录接口：免登录搜索、战绩查询退化为「角色名片」（昵称/角色ID/服务器/境界/总积分/场次） |

`wechat` 与 `heybox` 的角色绑定能力相同——绑定解绑与扫码渠道无关。

## 查询主流程

```
战绩查询 昵称
  ├─ 搜到了   → 更新数据 → 取列表/详情 → 返回
  └─ 没搜到
       ├─ 绑定「昵称」→ 轮询绑定结果
       │    ├─ 绑好了   → 重新搜索（这次能搜到）→ 更新 → 取数据 → 返回
       │    │              → 查完立刻解绑
       │    └─ 没绑好   → 「绑定失败：<原因>」
       └─ 绑定成功但查询失败 → 「绑定成功，查询失败：<原因>」
```

* 绑定用的是**你输入的原始昵称**，不做任何纠偏；所以大小写/空格不精确时会绑定失败（失败只是拿不到数据，不会绑错人）。
* **一次只能绑定一个号**：绑定是全局互斥的，但纯只读查询不受影响。
* 解绑在查询结束后**无条件执行**；绑定结果为 `waiting` 超时也会尝试解绑。
* 解绑失败会提示：`昵称 解绑失败，请发送：战绩解绑 昵称`——任何人都可以执行这条指令自行收尾。

## 指令

除管理员登录外，其余指令都可以作为普通消息直接发送，不需要 `/` 或其他唤醒词；带 `/` 的写法同样兼容。

| 指令 | 功能 |
| --- | --- |
| `战绩查询 <昵称> [模式]` | 排位/天人分数、近期有效对局数、常用英雄和场均伤害、振刀、击败；搜不到会自动走绑定兜底 |
| `详细查询 <昵称> [模式]` | 有效对局逐场列出英雄、击杀、伤害、恢复、振刀、存活 |
| `战绩绑定 <昵称> [模式]` | 跳过只读尝试，**强制**走「绑定 → 查询 → 解绑」通道 |
| `战绩解绑 <昵称>` | 手动解绑（**任何人可用**）；昵称与绑定时一致 |
| `永劫搜索 <昵称>` | 搜索玩家；**免登录**，未登录也能用 |
| `永劫赛季 <昵称> [模式] [当前/全部/赛季名]` | 查看某模式的赛季总览；内容过长时分条发送 |
| `/永劫登录` | 管理员按当前数据模式扫码登录 |
| `/永劫退出` | 管理员清除本地登录凭证 |
| `/永劫残留` | 管理员查看并重试解绑残留（进程被 kill 后的兜底） |

> **不支持按角色ID查询。** 输入看起来像角色ID时会明确提示改用昵称。
> 所有查询结果的首行都会同时给出昵称和 ID，例如 `昵称：<昵称>｜ID：<角色ID>`，
> 方便你对上号——但那一串 ID 不能拿回来查询。

模式写法（全部等价）：

```
单排 / 双排 / 三排                     ← 固定归到「天选」
天选单排 · 天选双排 · 天选三排
天人单排 · 天人双排 · 天人三排
天选之人三排 · 天人之战单排 · 快速匹配三排   ← 长写法兼容
快速单排 · 快速三排 · 无尽试炼
4 / 13 / 5 / 5000000 / 12 / 5000001 / 6 / 7 / 5000010   ← 原始 battle_tid
```

不指定模式时，插件先读取按时间排序的混合对局，排除快速等非排位模式，再按最新一场排位对局选择模式。

## 配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 数据模式 | `heybox` | `heybox` / `wechat` / `none`，见上 |
| 设备标识 device_id 策略 | `reuse` | `reuse` 复用首次生成的值（**建议默认**，官方客户端也是固定值）／`random` 每次登录换新／`off` 完全不发该参数 |
| 免登录搜索失败时回退到登录搜索 | 关闭 | **建议保持关闭**：搜索一律不带登录信息。开启后可能少绑定一次，代价是搜索请求会带上凭证 |
| 自动绑定兜底 | 开启 | 关闭后完全退回只读行为，不会产生任何绑定写操作 |
| 查询前先触发数据更新 | 开启 | 对应小黑盒的「更新数据」；关闭可加快查询速度 |
| 绑定负缓存（分钟） | 10 | 同一昵称绑定过仍查不到数据时，这段时间内不再重复绑定 |
| 残留绑定重试间隔（分钟） | 60 | 解绑失败留下的残留会定期重试；也可用 `/永劫残留` 手动重试 |
| 查询对局数 | 30 | 读取最近的混合对局；不设插件上限 |
| 对局列表分页参数 | `offset` | `offset` 发 `limit/offset`（推荐）；`page` 发 `page/page_size`（旧用法，疑似一直没生效）。把「查询对局数」调到 60 以上切换此项，对比「查询最近场次」即可确认 |
| 有效对局选择数 | 10 | 筛出目标模式后，最多尝试查询几场单局详情 |
| 英雄编号与名称对照 | 已有 30 条 | 可添加、展开修改条目；配置名称优先于接口名称 |
| A 用户请求间隔 | 4 秒 | 两个用户发起的查询之间最短多久。**只限制"发起"**，不延长查询本身，与 B 独立。0 = 关闭 |
| B 机器人请求每项间隔 | 0 秒（关） | **每一次**上游请求之间的最小间隔（搜索/绑定/轮询/更新/列表/详情/解绑全覆盖） |
| C 仅单局查询之间间隔 | 4 秒 | **只管相邻两次单局详情**，不影响其它请求。与 B 取较大值，不叠加。0 = 关闭 |
| 绑定结果轮询间隔 | 2 秒 | 绑定后每隔多久问一次「绑好了没」，最多 5 次。**建议保持默认**（小黑盒官方节奏） |
| 数据更新重试间隔 | 3 秒 | 「更新数据」返回 waiting/updating 时的重试间隔，最多 3 次。**建议保持默认** |
| 解绑重试间隔 | 2 秒 | 解绑失败后隔多久重试，最多 3 次。**建议保持默认**，调小容易连撞限流 |
| 启用群聊白名单 | 关闭 | 开启后只允许名单内 QQ 群查询；私聊不受影响 |
| 允许登录二维码发到群里 | 关闭 | 开启后管理员可在群里扫码 |
| 收到请求立刻回执 | 关闭 | 战绩查询／详细查询／战绩绑定／永劫赛季 会**先**回一条「已收到」 |
| 回执方式 | 引用原消息 | 引用原消息 / 纯文本 / QQ 表情回应 |
| 回执文字 | 已收到请求，正在查询… | 回执方式为引用或纯文本时发送的文字 |
| QQ 表情回应 ID | 277 | 回执方式为 QQ 表情回应时使用；仅 aiocqhttp 生效 |
| 战绩结果回复方式 | 引用原消息 | 只作用于上述四条指令的战绩正文：引用原消息 / 纯文本 / `at`（@触发者，走底层 API） |

三个间隔各管一段，互不叠加：

* **A（用户请求间隔）** 只防"多人反复发起"，**独立**于 B/C，不延长一次查询本身。
* **B（机器人请求每项间隔）** 覆盖机器人发出的**每一次**上游请求：搜索、绑定、状态轮询、更新、对局列表、单局详情、解绑。
* **C（仅单局查询之间间隔）** 只管**相邻两次单局详情**；B 包含 C，所以详情之间的实际间隔取 `max(B, C)`，**不是相加**。

三者都可以设 `0` 即关闭。默认 `A=4 / B=0 / C=4`，等价于旧版本行为。
所有请求都要经过 `_paced()` 排队，因此一次查询的请求成本上限是可预期的。

## 行为边界

* 搜不到昵称 → 提示用 `永劫搜索` 核对（搜索是独立指令，插件不会替你发）。
* **输入像角色ID → 明确提示「不支持按角色ID查询」，不会去搜索、也不会触发绑定。**
* 同名玩家 → 要求先用 `永劫搜索` 查看玩家，避免查错人。
* 命中限流或登录失效 → 停止后续请求并明确提示原因。
* 无绑定模式下，`详细查询` 和 `永劫赛季` 会提示该模式不支持，而不是回一堆空数据。

## 失败时说什么

自动兜底路径（`战绩查询` / `详细查询`）**不会出现「绑定」二字** —— 用户没要求过绑定，
说了只会让他困惑，甚至怀疑插件在自己账号上做了什么。

| 情况 | 回复 |
| --- | --- |
| 昵称搜不到、也绑不上（**多半是名字写错**） | `没找到「X」。` 下面列出「昵称可能拼错」「也可能只是服务器排队繁忙」，并提示 `永劫搜索 X` 核对 |
| 排队超时 / 接口异常 / 限流 | `搜索「X」失败，请稍后再试。` |
| 找到了角色但取不到数据 | `搜索「X」成功，但没能取到数据，请稍后再试。` |

只有你**显式发送** `战绩绑定` 时才会出现「绑定」字样（那是你主动要求的）：
`绑定「X」失败：<原因>，请稍后再试。`

内部细节（状态、原始原因、昵称）全部写进日志，用户看到的文案不承担排障职责。

> 为什么要分成"名字问题"和"技术问题"：前者用户**自己能解决**（去核对昵称），
> 后者只能等。混成一句话，用户不是白白重试就是一直改昵称。

## 风险提示

* 自动绑定会在你的小黑盒账号上产生**真实写操作**（绑定 + 解绑各一次）。关闭「自动绑定兜底」即可完全避免。
* 解绑失败会留残留绑定；插件会重试并提示，请留意 `/永劫残留`，必要时手动执行 `战绩解绑 <昵称>`。
* 上游为非公开接口，随时可能变更或收紧。请低频使用，不要做批量轮询。
* `战绩解绑` 权限为任何人：群里任何人都能解掉你账号上的绑定（最坏是让并发查询拿不到数据，
  不会泄露数据或影响账号安全）。每次手动解绑都会记录操作者到日志。
